# Quickstart：搶答歷史紀錄 CSV 匯出驗證

## 前置條件與啟動
同 [Step 3](../003-sheet-question-form/quickstart.md)～[Step 7](../007-bundle-submit/quickstart.md)：
`backend/.env` 設好機器人金鑰、試算表已共用給機器人；前後端啟動方式相同。

## 自動化測試
```bash
cd backend && uv run pytest
cd frontend && npx tsc -b      # 於 frontend/ 內 nvm use
```
預期通過：內容與欄位、多輪與排序、題組各題一列、與看板／快照逐筆一致、BOM／CRLF／跳脫、公式安全、
未授權與網址憑證無效、搶答中／已結束／房間結束後皆可匯出、唯讀、6000 列規模。既有 Step 1～7 測試仍全數通過。

## 手動驗證情境

準備：老師貼單題範例（Q1～Q6），在預覽把 Q3、Q4 設為題組後建立房間；「第 1 組」「第 2 組」各開一個視窗加入。

| # | 步驟 | 預期（對應規格） |
|---|------|------------------|
| 1 | 尚未有人送出時按老師端「匯出紀錄」 | 顯示「尚無送出紀錄可匯出」，沒有下載任何檔案（US1-5、FR-004） |
| 2 | 老師開始搶答；第 1 組先、第 2 組後送出 Q1；第 1 組送出題組 Q3+Q4 | 老師端進度板顯示名次 |
| 3 | 老師按「匯出紀錄」 | 2 秒內瀏覽器下載 `搶答紀錄_<代碼>_<日期>.csv`（US1-1、SC-001） |
| 4 | 用 Excel 直接雙擊開啟 | 中文正常顯示、不亂碼；標題列為「輪次、題號、題組、組別、答案、接收時間、排名」（FR-016） |
| 5 | 檢視內容 | Q1 第 1 組排名 1、第 2 組排名 2；Q3、Q4 各一列、題組欄為「Q3、Q4」、時間與排名相同（US1-3、US2-2） |
| 6 | 與老師端進度板、「本輪送出」逐筆核對 | 組別、題目、答案、時間、名次完全一致（US2-6、SC-002） |
| 7 | 第 2 組送出一個答案 `=1+1`、另一題送出含逗號與換行的答案 | — |
| 8 | 再匯出並開啟 | `=1+1` 顯示為文字 `'=1+1`、不被計算；含逗號與換行的答案在單一儲存格、列數不變（US2-3、US2-4、SC-004、SC-005） |
| 9 | 老師結束搶答、再開始第二輪並送出一題，再匯出 | CSV 含兩輪，以輪次欄區分，排序為輪次→題目順序→名次（US2-1、FR-012） |
| 10 | 老師按「結束房間」，在「房間已結束」畫面按「匯出紀錄」 | 仍可下載完整紀錄，與結束前一致（US4-2、SC-008） |
| 11 | 用 `curl` 不帶憑證、帶錯誤憑證、把憑證放網址參數呼叫端點 | 皆回 401 且不含任何答案（US3-1、SC-006） |
| 12 | 老師用恢復碼在另一瀏覽器回復身分；舊瀏覽器再按「匯出紀錄」 | 舊瀏覽器被視為身分失效；新瀏覽器可匯出完整紀錄（US3-2、US3-4） |
| 13 | 檢視學生端畫面與開發者工具中的 WebSocket 訊息 | 找不到任何匯出入口或匯出內容（US3-3、SC-007） |
| 14 | 重啟後端後以舊憑證匯出 | 顯示「紀錄已不存在，請於活動結束後盡快匯出」，不下載空檔（US4-3） |

契約見 [rest-api.md](./contracts/rest-api.md)、[csv-format.md](./contracts/csv-format.md)；資料見 [data-model.md](./data-model.md)。

## 實作後的圖表一致性檢查（Constitution VI）
比對 `diagrams/*.puml` 與程式（匯出服務、`ExportRow` 欄位與排序、老師憑證驗證、`NO_RECORDS`／`RECORDS_GONE`、公式防護）；
不一致時修正程式或更新圖表，並重新產圖：
```bash
java -jar plantuml.jar -charset UTF-8 -tpng diagrams/*.puml
```
（本機若無 Graphviz，加 `-Playout=smetana`。）
