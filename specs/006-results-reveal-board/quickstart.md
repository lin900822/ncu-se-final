# Quickstart：結果公布看板驗證

## 前置條件與啟動
同 [Step 4](../004-group-answer-submit/quickstart.md)、[Step 5](../005-answer-ranking-board/quickstart.md)（`backend/.env`、共用給機器人的試算表；前後端啟動方式相同）。

## 自動化測試
```bash
cd backend && uv run pytest
cd frontend && npx tsc -b      # 於 frontend/ 內 nvm use
```
預期通過：結算內容正確、無人搶答、與老師看板一致、公布前不外洩、公布後只含第 1 名、離線／重整／晚加入還原、同組多視窗同步、重複結束不重複公布、新一輪離開結果頁。

## 手動驗證情境

準備：老師建立房間（單題範例 Q1～Q6）；「第 1 組」「第 2 組」「第 3 組」各開一個視窗（第 1 組另開第二個視窗）；老師按「開始搶答」。

| # | 步驟 | 預期（對應規格） |
|---|------|------------------|
| 1 | 搶答中檢視學生端畫面與 WebSocket 訊息 | 找不到結果、第一名或他組答案（US3、SC-003） |
| 2 | 第 1 組先、第 2 組後送出 Q1；第 3 組送 Q2；Q3 無人送出 | 老師端進度板各題最快組別正確 |
| 3 | 老師按「結束搶答」 | 所有學生畫面 2 秒內自動切換至結果頁（US1、SC-001） |
| 4 | 看結果頁 Q1 | 顯示「第 1 組」與其答案；**看不到**第 2 組的答案與名次（FR-004、SC-004） |
| 5 | 看結果頁 Q2、Q3 | Q2 顯示第 3 組與答案；Q3 顯示「本題無人搶答」（SC-006） |
| 6 | 在第 1 組視窗查看 | Q1 標示「本組搶下」；第 1 組第二個視窗顯示相同結果（FR-006、FR-009） |
| 7 | 與老師端進度板比對 | 每題第一名組別與答案完全一致（SC-002） |
| 8 | 結束時先讓某視窗離線，再重連；另重新整理一個視窗 | 立即顯示相同結果頁（US2、SC-005） |
| 9 | 結束後新開一個視窗以同代碼加入 | 直接看到結果頁 |
| 10 | 老師再次按「結束搶答」 | 無重複公布、結果不變（FR-011） |
| 11 | 老師再按「開始搶答」 | 學生離開結果頁回到作答，不殘留舊結果（US3、SC-008） |

契約見 [websocket.md](./contracts/websocket.md)；資料見 [data-model.md](./data-model.md)。
