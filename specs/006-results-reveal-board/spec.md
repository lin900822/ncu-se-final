# Feature Specification: 搶答結果公布看板

**Feature Branch**: `006-results-reveal-board`（本專案未建立分支，於 master 開發；規格目錄為 `specs/006-results-reveal-board`）

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "Step 6: 搶答結果公布看板。目標：活動結束時的結果揭曉。驗證效果：老師點擊「結束搶答」後，所有學生端畫面自動切換至結果頁，清楚列出 Q1～Q5 分別由哪一組搶下第一名以及其填寫的答案。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 結束搶答後學生自動看到結果頁 (Priority: P1)

老師按下「結束搶答」後，所有在線學生的畫面自動切換為「結果頁」，逐題列出該題由哪一組搶下第一名，以及該組填寫的答案。學生不需要重新整理或任何操作。

**Why this priority**: 這是本步驟指定的驗證效果，也是整個活動的結果揭曉時刻（Constitution 原則 III 允許的「結算後公布獲勝內容」）。

**Independent Test**: 數組在 Q1～Q5 各自送出答案後，老師按「結束搶答」；所有學生畫面在 2 秒內自動切換到結果頁，Q1～Q5 各列出第一名組別與其答案，且與老師端看板的各題最快組別一致。

**Acceptance Scenarios**:

1. **Given** 搶答進行中且各題已有組別送出, **When** 老師點擊「結束搶答」, **Then** 所有在線學生畫面在 2 秒內自動切換至結果頁，無須重新整理。
2. **Given** 結果頁已顯示, **When** 學生查看某題, **Then** 看到題號、搶下第一名的組別名稱與該組填寫的答案。
3. **Given** 某題有多組送出, **When** 結果頁公布, **Then** 該題只公布第 1 名的組別與答案；其餘組別的答案與名次不公布（Constitution 原則 III：僅公布獲勝內容）。
4. **Given** 某題在本輪沒有任何組別送出, **When** 結果頁公布, **Then** 該題顯示「本題無人搶答」。
5. **Given** 學生自己的組別是某題第 1 名, **When** 查看結果頁, **Then** 該題以醒目標記指出「本組搶下」，方便辨認。
6. **Given** 結果頁每題的組別與答案, **When** 與老師端進度板比對, **Then** 每題的第一名組別與答案完全一致。

---

### User Story 2 - 結果頁在斷線、重整與晚加入時仍正確 (Priority: P1)

結果以系統記錄為準。學生在公布時處於離線、事後重新整理、或活動結束後才加入，都看得到同一份結果。

**Why this priority**: 即時同步與斷線還原是 Constitution 的硬性約束；若漏看就失去揭曉的意義。

**Independent Test**: 結束搶答時讓某學生視窗離線，重連後立即顯示相同的結果頁；重新整理也相同。

**Acceptance Scenarios**:

1. **Given** 結束搶答時某學生視窗離線, **When** 它重新連線, **Then** 立即顯示結果頁與相同內容。
2. **Given** 結果頁顯示中, **When** 學生重新整理頁面, **Then** 重新加入後仍顯示結果頁。
3. **Given** 搶答已結束, **When** 有組別以代碼與組名加入（含新視窗）, **Then** 加入後直接看到結果頁。
4. **Given** 同一組有多個視窗, **When** 結果公布, **Then** 所有視窗同時顯示相同結果。

---

### User Story 3 - 結果公布前不外洩、新一輪開始後回到作答 (Priority: P1)

在老師結束搶答之前，學生端不會看到任何結果、領先組別或名次；結果只在結算時一次公布。老師再次開始新一輪搶答時，學生畫面離開結果頁、回到作答畫面，且上一輪結果不再顯示。

**Why this priority**: 守住作答保密（原則 III），並確保輪次切換時畫面不殘留舊結果。

**Independent Test**: 搶答中檢視學生端所有畫面與資料，找不到任何第一名或答案；結束搶答後才出現；再次開始搶答後結果頁消失。

**Acceptance Scenarios**:

1. **Given** 搶答進行中, **When** 檢查任何學生連線收到的資料, **Then** 找不到他組組名、名次、領先資訊或答案（維持 Step 4、5 的保密）。
2. **Given** 結果頁顯示中, **When** 老師再次按「開始搶答」, **Then** 學生畫面回到作答畫面，上一輪結果不再顯示，各題為未送出狀態（沿用 Step 2～4）。
3. **Given** 等待搶答階段（尚未開始過）, **When** 學生查看畫面, **Then** 沒有結果頁。
4. **Given** 房間已被老師結束, **When** 學生仍在線, **Then** 沿用既有的房間已結束提示，不再顯示結果頁內容的更新。

---

### User Story 4 - 老師端確認結果公布 (Priority: P2)

老師按下「結束搶答」後，老師端也能看到與學生端一致的最終結果（每題第一名與答案），確認學生看到的內容。

**Why this priority**: 老師需要核對公布內容；老師端進度板（Step 5）已有資料，僅需標示為最終結果，不阻擋學生端核心流程。

**Independent Test**: 結束搶答後，老師端的最終結果與學生端結果頁逐題一致。

**Acceptance Scenarios**:

1. **Given** 老師已結束搶答, **When** 查看老師端, **Then** 看到各題第一名組別與答案，與學生端結果頁一致。
2. **Given** 老師端重新整理或換裝置回復, **When** 回到老師端, **Then** 仍看到最終結果。

---

### Edge Cases

- 學生在老師按下「結束搶答」的同時送出答案：以系統收到的順序為準（沿用 Step 4）；結果只含結算前已被接受的送出。
- 某題只有一組送出：該組即為第一名並公布其答案。
- 全部題目都無人送出：結果頁列出每題「本題無人搶答」，不得空白或出錯。
- 同一組在多題都是第一名：各題分別列出，不做合併或防壟斷調整（本步驟不處理遞補）。
- 答案含特殊字元或換行：原文保留並安全顯示，不造成畫面錯亂。
- 老師重複按「結束搶答」：不重複公布、不改變已公布的結果。
- 結果頁顯示後老師再開始新一輪：結果頁關閉，舊輪紀錄仍保留在系統中，不被覆寫。
- 房間被結束或閒置逾時：沿用既有行為；已公布的結果不再變動。
- 題目數量不是 5 題：結果頁依實際題目數逐題列出（Q1～Q5 僅為驗證範例）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 老師結束搶答時，系統 MUST 依該輪的送出順位（Step 5）產生結果：每題第 1 名的組別名稱與其送出的答案；結果於結算當下確定。
- **FR-002**: 結果公布後，所有在線學生畫面 MUST 在 2 秒內自動切換為結果頁，不需任何手動操作。
- **FR-003**: 結果頁 MUST 依題目順序逐題列出：題號、搶下第一名的組別名稱、該組的答案；題號標示沿用既有題目標示（含題組小題）。
- **FR-004**: 每題 MUST 只公布第 1 名的組別與答案；其餘組別的組名、名次與答案 MUST NOT 公布（Constitution 原則 III）。
- **FR-005**: 本輪沒有任何有效送出的題目，結果頁 MUST 顯示「本題無人搶答」。
- **FR-006**: 結果頁 MUST 標示學生自己的組別搶下的題目（如「本組搶下」）。
- **FR-007**: 在老師結束搶答之前，系統 MUST NOT 向任何學生連線傳送結果、第一名組別、名次或他組答案；結果只在結算時公布（維持 Step 4、5 的保密）。
- **FR-008**: 學生在結果公布時離線、重新整理、或結束後才加入，系統 MUST 於加入／重連時還原並顯示相同的結果頁；結果以系統記錄為準，不依賴客戶端狀態。
- **FR-009**: 同一組別的所有視窗 MUST 同時顯示相同結果。
- **FR-010**: 老師再次開始新一輪搶答時，學生畫面 MUST 離開結果頁回到作答畫面，上一輪結果 MUST NOT 再顯示；舊輪的送出紀錄與順位仍保留（僅追加，不覆寫）。
- **FR-011**: 已公布的結果 MUST NOT 被靜默改寫；老師重複結束搶答 MUST NOT 產生新的或不同的結果。
- **FR-012**: 結果頁各題的第一名組別與答案 MUST 與老師端進度板（Step 5）完全一致，且僅依系統端順位（非客戶端時間）。
- **FR-013**: 老師端 MUST 能看到與學生端一致的最終結果，重整或換裝置回復後仍可見。
- **FR-014**: 本步驟的「第一名」＝該題最快被系統收到的有效送出；MUST NOT 做防壟斷遞補、老師仲裁、計分或回填試算表（留待後續步驟）。
- **FR-015**: 結果僅以組別為單位呈現，不得出現個別學生身分（Constitution 原則 I）。

### Key Entities *(include if feature involves data)*

- **結果 (Result)**: 某一輪結算時每題的公布內容：題目、第一名組別名稱、該組答案（或「無人搶答」）；由該輪各題第 1 名的送出紀錄確定，結算後不可改寫。
- **結果公布 (Result Reveal)**: 結束搶答當下對全體學生與老師的一次揭曉；對應輪次，每輪只公布一次。
- **送出順位 (Submission Rank)**、**送出紀錄 (Submission)**、**組別**、**題目**、**房間**: 沿用 Step 1～5。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 老師按「結束搶答」後，所有在線學生畫面在 2 秒內自動切換至結果頁（無須手動操作）。
- **SC-002**: 結果頁列出的每題第一名組別與答案，與老師端進度板比對一致率為 100%。
- **SC-003**: 結果公布前（搶答進行中與等待中），學生連線收到的資料中出現結果、第一名組別或他組答案的次數為 0（以自動化檢查驗證）。
- **SC-004**: 結果頁中，除第一名外的其他組別組名、名次與答案出現次數為 0。
- **SC-005**: 離線、重新整理或結束後才加入的學生，100% 能立即看到相同的結果頁。
- **SC-006**: 沒有任何送出的題目，100% 顯示「本題無人搶答」，不出現空白或錯誤。
- **SC-007**: 學生在 5 秒內能從結果頁找出任一題的第一名組別與答案，以及自己的組別搶下哪些題。
- **SC-008**: 新一輪開始後，100% 的學生畫面離開結果頁且不殘留上一輪結果。

## Assumptions

- 「結算」時點＝老師按「結束搶答」；每輪結束時公布一次，不提供老師手動延後或隱藏。
- 「搶下第一名」＝該題最快被系統收到的有效送出（Step 5 的第 1 名）；本步驟尚未實作防壟斷遞補與老師仲裁，因此公布的是「最快送出」結果，後續步驟若引入仲裁或遞補，結果內容將隨之調整。
- 結果頁只公布各題第一名的組別與答案；不公布其他組別的答案與名次（Constitution 原則 III：其餘組別僅能於結算後看到獲勝內容）。
- 結果頁以既有題目標示（含題組小題）列題；是否一併顯示題目文字不在本步驟範圍（維持結算後隱藏題目文字的既有規則）。
- 結果頁僅在「已結束搶答」階段顯示；新一輪開始即隱藏，舊輪結果不再提供給學生查看（歷程仍保留於系統，供後續匯出）。
- 結果頁不顯示各組領先題數、分數或排行榜；那屬於後續計分步驟。
- 老師端沿用 Step 5 的進度板作為最終結果，不新增獨立頁面。
- 沿用專案 Constitution：組別為唯一單位、系統端時間與順位為準、紀錄僅追加、作答保密（結算後僅公布獲勝內容）、不蒐集學生個資。
