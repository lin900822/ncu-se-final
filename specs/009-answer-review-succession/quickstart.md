# Quickstart：老師端人工審核與順位遞補驗證

## 前置條件與啟動
同 [Step 3](../003-sheet-question-form/quickstart.md)～[Step 8](../008-export-records-csv/quickstart.md)：
`backend/.env` 設好機器人金鑰、試算表已共用給機器人；前後端啟動方式相同。

## 自動化測試
```bash
cd backend && uv run pytest
cd frontend && npx tsc -b      # 於 frontend/ 內 nvm use
```
預期通過：遞補（連續駁回、全部駁回、恢復）、隨機序列性質測試、題組整組審核、時機與驗證、冪等與併發、原始資料不變、
學生／老師同步、被駁回者不外洩、重連還原、權限、看板與領先題數、匯出追加欄位。既有 Step 1～8 測試（含更新後的欄位數與靜態審核允許清單）仍全數通過。

## 手動驗證情境

準備：老師貼單題範例（Q1～Q6），在預覽把 Q3、Q4 設為題組後建立房間；「第 1 組」「第 2 組」「第 3 組」各開一個視窗加入
（第 3 組可再開第二個視窗）；老師開始搶答。

| # | 步驟 | 預期（對應規格） |
|---|------|------------------|
| 1 | 第 1 組先、第 2 組後、第 3 組最後送出 Q1（第 1 組故意填亂填答案）；第 1 組另整組送出題組 Q3+Q4，第 2 組也送出該題組 | 老師進度板顯示各題名次 |
| 2 | 搶答**進行中**檢視老師端結果／進度板 | 沒有可用的「駁回/無效」（US3-1、FR-005） |
| 3 | 老師按「結束搶答」 | 學生自動切到結果頁，Q1 顯示第 1 組與其答案（Step 6） |
| 4 | 老師在 Q1 第 1 組旁點「駁回/無效」 | 展開理由輸入，理由為空時「確認駁回」不可按；可選常用理由或自行輸入（FR-002） |
| 5 | 選「答案錯誤」按「確認駁回」 | 老師端 Q1 第 1 組標示「已駁回」並顯示理由；第 2 組的遞補後名次為 1（US1-1、US3-3） |
| 6 | 檢視 3 個學生視窗 | 2 秒內 Q1 改顯示第 2 組與其答案；第 2 組視窗標示「本組搶下」、第 1 組視窗不再標示；頁面顯示「老師已更新結果」（US2-1～3、SC-002） |
| 7 | 在學生開發者工具檢視 WebSocket 訊息，搜尋第 1 組的組名與其亂填答案、駁回理由 | 更新後的訊息中找不到（US2-4、SC-004） |
| 8 | 重新整理任一學生視窗、另開新視窗以同代碼加入 | 立即看到審核後的結果，與其他視窗相同（US2-5、SC-005） |
| 9 | 老師再駁回第 2 組的 Q1 | Q1 改由第 3 組取得；各視窗同步（US1-2） |
| 10 | 老師對 Q1 第 3 組也駁回 | Q1 顯示「本題無有效答案」（US1-3） |
| 11 | 老師對 Q1 第 1 組按「恢復有效」並填理由 | Q1 回到第 1 組（依原始名次），各視窗同步（US4-1） |
| 12 | 老師駁回第 1 組的題組 Q3+Q4 | 題組整組一起被駁回，結果改為第 2 組，題組內兩題同一組別；不能只駁回其中一題（US1-7） |
| 13 | 連續快速點擊同一筆「確認駁回」，或在兩個老師視窗同時操作 | 審核紀錄只有一筆、只遞補一名（US4-3、SC-009） |
| 14 | 檢視老師端「審核紀錄」 | 每次駁回／恢復各一筆：時間、組別、題目、動作、理由（US4-2、SC-006） |
| 15 | 按「匯出紀錄」並以 Excel 開啟 | 十一欄；被駁回列為「無效」、遞補後名次空白；原始排名欄不變；理由與時間正確（US4-4、SC-008） |
| 16 | 以 `curl` 不帶憑證、錯誤憑證、憑證放網址呼叫審核端點 | 皆回 401，結果不變（US3-6、SC-007） |
| 17 | 老師開始新一輪搶答後，嘗試審核舊輪（或舊畫面送 `round: 1`） | 被拒絕並說明只能審核最新一輪；舊輪審核紀錄仍保留（US3-4） |
| 18 | 老師結束房間後嘗試審核 | 被拒絕（房間已結束）；仍可查看與匯出（US3-5） |
| 19 | 開新房間，學生在「等待搶答」階段的畫面 | 顯示規則說明「老師可審核答案；答案被判定無效時，名次由次順位組別遞補」（FR-022） |

契約見 [rest-api.md](./contracts/rest-api.md)、[websocket.md](./contracts/websocket.md)、[csv-format.md](./contracts/csv-format.md)；資料見 [data-model.md](./data-model.md)。

## 實作後的圖表一致性檢查（Constitution VI）
比對 `diagrams/*.puml` 與程式（`ReviewRecord`／`EffectiveResult`、審核服務的驗證順序與重複判斷、`review_updated`／`round_result.reviewed`
的受眾與內容、有效第一名推導、`ExportRow` 的四個審核欄位）；不一致時修正程式或更新圖表，並重新產圖：
```bash
java -jar plantuml.jar -charset UTF-8 -tpng diagrams/*.puml
```
（本機若無 Graphviz，加 `-Playout=smetana`。）
