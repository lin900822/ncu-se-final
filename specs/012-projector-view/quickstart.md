# Quickstart：教室大螢幕投影專用視圖驗證

## 前置條件與啟動
同 [Step 3](../003-sheet-question-form/quickstart.md)～[Step 11](../011-win-cap-cooldown/quickstart.md)：`backend` 以 uv 啟動、前端 `npm run dev`（或已建置的前端）；老師貼單題範例（Q1～Q6）建立房間。

## 自動化測試
```bash
cd backend && uv run pytest
cd frontend && npx tsc -b && npm run build && npm run lint
```
預期通過：憑證與唯讀、錯誤一致、不計為組別、搶答中零洩漏（含題組與多組）、各階段內容、即時更新、Closed 與無題目房間、與學生／老師結果一致、多輪累計得分與並列、確定性與唯讀、countdown 只發一次且不補播；既有 340 個測試不需修改即通過；lint 警告數不多於修改前。

## 手動驗證情境

準備：老師端建立房間；「第 1 組」「第 2 組」「第 3 組」各開一個學生視窗；另開投影視圖。

| # | 步驟 | 預期（對應規格） |
|---|------|------------------|
| 1 | 老師端按「開啟投影視圖」 | 新分頁開啟 `/projector?code=…&key=…`；網址不含老師憑證；老師端可「複製投影網址」（US1-1） |
| 2 | 檢視投影畫面（等待搶答） | 大字顯示房間代碼；找不到任何按鈕或輸入欄位；字級明顯放大（US1-3） |
| 3 | 三個學生組別依序加入 | 投影即時出現各組名，且**不**出現在老師端組別清單之外的任何位置變化（US1-2、6） |
| 4 | 老師按「開始搶答」 | 投影播放 3、2、1、開始！動畫後切到進度看板；學生端同時開放，輸入不被延後（US2-1、2） |
| 5 | 第 1 組送 Q1、Q3；第 2 組送 Q3 | 投影 Q1、Q3 變「已有組別送出」、進度 2／6；全程**看不到**組名、答案、名次（US2-3、4） |
| 6 | 重新整理投影頁（搶答中） | 直接顯示進度看板，**不重播**倒數（US2-5、US4-2） |
| 7 | 老師按「結束搶答」 | 投影顯示各題得主組名＋答案（無人搶答的題標示無人搶答）與累計得分排行榜；與學生結果頁逐題一致（US3-1、2） |
| 8 | 老師駁回第 1 組 Q1 | 投影看板與排行榜 3 秒內更新；看不到駁回理由與名次（US3-3、FR-008） |
| 9 | 建立設上限 1 的房間重做 5～7 | 讓位後的得主與得分顯示一致（US3-4） |
| 10 | 再按「開始搶答」開第二輪 | 再次倒數；排行榜維持累計（不含第 2 輪），看板回到匿名進度（US3-5、6、US2-6） |
| 11 | 中斷投影電腦網路再恢復 | 顯示「連線中斷，重新連線中」，恢復後 5 秒內還原為目前內容（US4-1、SC-007） |
| 12 | 老師結束房間 | 投影顯示「房間已結束」並保留最後看板與排行榜（US4-3） |
| 13 | 以錯誤 key 或老師 token 開 `/projector` | 顯示「無法顯示」，不透露房間是否存在；不再重連（US1-7） |
| 14 | 建立不含試算表的房間並開投影 | 只顯示代碼與組別，無題目看板（US4-4） |
| 15 | 系統設定「減少動態效果」後開始搶答 | 倒數改為逐秒靜態數字，內容不遺失（FR-014） |
| 16 | 30 題、20 組的房間投影（以假資料） | 在 1920×1080 單一畫面完整呈現，無需捲動（SC-005） |

契約見 [rest-api.md](./contracts/rest-api.md)、[websocket.md](./contracts/websocket.md)。

## 實作後的圖表一致性檢查（Constitution VI）
比對 `diagrams/*.puml` 與程式（`projector_key`、`ProjectorView`／`GroupScore` 欄位、投影服務的唯讀通道與觸發事件、搶答中不含組名與答案、countdown 一次性與不補播）；不一致時修正程式或更新圖表並重新產圖：
```bash
java -jar plantuml.jar -charset UTF-8 -tpng diagrams/*.puml
```
（本機若無 Graphviz，加 `-Playout=smetana`。）
