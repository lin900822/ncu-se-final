# Quickstart：順位與進度板驗證

## 前置條件與啟動
同 [Step 4](../004-group-answer-submit/quickstart.md)（`backend/.env`、共用給機器人的試算表；前後端啟動方式相同）。

## 自動化測試
```bash
cd backend && uv run pytest
```
預期通過：名次唯一且連續、`asyncio.gather` 並發 100 次不並列、先處理者名次較佳且忽略客戶端時間、拒絕／重複送出不佔名次、看板推導（最快組別、名次清單、領先題數、尚無送出）、重連還原、新一輪清空但舊紀錄保留、學生訊息不含 `rank`／`board`／他組組名。

## 手動驗證情境

準備：老師建立房間；「第 1 組」「第 2 組」「第 3 組」各開一個視窗（A、B、C）；老師開啟老師端並按「開始搶答」。

| # | 步驟 | 預期（對應規格） |
|---|------|------------------|
| 1 | 看老師端進度板 | 所有題目顯示「尚無組別送出」（US2 情境 3） |
| 2 | A、B 兩台裝置幾乎同時對 Q1 送出 | 老師端 Q1 判出一個第 1 名、一個第 2 名，不並列，2 秒內顯示最快組別名稱（US1、SC-001、SC-003） |
| 3 | C 之後送出 Q1 | C 為第 3 名；先前名次不變（US1 情境 3、FR-005） |
| 4 | 某組對 Q1 再送出（連點） | 名次與時間不變，無新紀錄（US1 情境 5、SC-006） |
| 5 | 對空白答案送出 | 被拒絕，不佔名次（FR-004） |
| 6 | 只有 B 送出 Q2 | 進度板 Q2 最快為 B；「各組領先題數」更新（US2 情境 4） |
| 7 | 重新整理老師端／以恢復碼換裝置 | 看板還原為一致內容（US2 情境 5、SC-004） |
| 8 | 調整學生裝置時鐘後再次送出另一題 | 名次仍只依抵達先後（US1 情境 4、SC-002） |
| 9 | 檢視 A、B、C 的 WebSocket 訊息 | 找不到名次、領先組別、看板、他組組名（US3、SC-005） |
| 10 | 老師再次「開始搶答」 | 看板清空為空白新一輪；舊紀錄仍在紀錄中（FR-011） |
| 11 | 老師「結束搶答」後嘗試送出 | 被拒絕，不產生名次 |

契約見 [websocket.md](./contracts/websocket.md)；資料見 [data-model.md](./data-model.md)。

## 實作後的圖表一致性檢查（Constitution VI）
比對 `diagrams/*.puml` 與程式（名次欄位、順位服務、看板推送僅送老師）；不一致時修正程式或更新圖表並重跑 `plantuml -tpng diagrams/*.puml`。
