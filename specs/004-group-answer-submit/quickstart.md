# Quickstart：答案提交驗證

## 前置條件與啟動
同 [Step 1](../001-room-join/quickstart.md) 與 [Step 3](../003-sheet-question-form/quickstart.md)（`backend/.env` 與共用給機器人的試算表；前後端啟動方式相同）。

## 自動化測試
```bash
cd backend && uv run pytest
```
預期通過：提交與驗證、同組同題連點與並發只一筆、他組連線訊息不含答案／組名／組數／時間、階段閘門、同組多視窗與上限、重連還原、新一輪重設但舊紀錄保留。

## 手動驗證情境

準備：老師用單題範例建立房間；組別「第 1 組」開**兩個**視窗（視窗 A、B），「第 2 組」開一個視窗 C；老師按「開始搶答」。

| # | 步驟 | 預期（對應規格） |
|---|------|------------------|
| 1 | 視窗 A 在 Q1 輸入「CPU」並按「送出」 | Q1 變為「已送出」並鎖定，Q2 仍可輸入（US1、SC-001） |
| 2 | 看視窗 B | 2 秒內 Q1 顯示「已送出」與「CPU」（唯讀）（US2、SC-002） |
| 3 | 看視窗 C（第 2 組） | Q1 只出現「本題已有組別送出」，**沒有**「CPU」、組名、組數（US3、SC-003） |
| 4 | 在視窗 C 的 Q1 輸入並送出 | 不受影響，可正常送出；老師端出現兩筆（US3、FR-013） |
| 5 | 老師端查看 | 看到「第 1 組：Q1＝CPU＋時間」與第 2 組的紀錄（US4、SC-007） |
| 6 | 視窗 A 對已送出的 Q1 再按送出（或連點 10 次） | 無變化，只有一筆紀錄（SC-004） |
| 7 | A、B 同時對 Q2 送出不同內容 | 只留先到的一筆，另一視窗改顯示先到者的內容（US2 情境 2） |
| 8 | 對空白答案按送出 | 提示請填寫答案，不送出（US1 情境 2） |
| 9 | 老師按「結束搶答」後嘗試送出 | 被拒絕，仍鎖定（FR-003、SC-006） |
| 10 | 重新整理視窗 B | 立即還原 Q1「已送出」與內容；視窗 C 還原「已有組別送出」（FR-007、SC-005） |
| 11 | 老師再次「開始搶答」 | 所有「已送出」與提示清空，老師端清單只顯示新一輪，舊紀錄仍可在紀錄中看到（FR-012） |
| 12 | 第 1 組開到第 11 個視窗 | 被拒絕並提示視窗數已達上限（FR-014） |
| 13 | 瀏覽器開發者工具看視窗 C 的 WebSocket 訊息 | 找不到「CPU」、「第 1 組」（SC-003） |

契約見 [websocket.md](./contracts/websocket.md)；資料見 [data-model.md](./data-model.md)。

## 實作後的圖表一致性檢查（Constitution VI）
比對 `diagrams/*.puml` 與程式（`Submission`、提交服務、防重複、三種扇出、同組多視窗）；不一致時修正程式或更新圖表並重跑 `plantuml -tpng diagrams/*.puml`。
