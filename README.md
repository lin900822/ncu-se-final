# 課堂搶答數位化系統 — Step 1：房間建立與學生加入

老師建立房間取得代碼，學生輸入代碼與組名加入，老師端即時列出已加入的組別。

## 前置需求

- [nvm](https://github.com/nvm-sh/nvm)（前端使用 Node.js 22 LTS）
- [uv](https://docs.astral.sh/uv/)（後端 Python 3.12 由 uv 自動取得）

## 啟動

需要開**兩個終端機**，先啟動後端，再啟動前端。以下指令都從專案根目錄開始。

### 1. 後端（終端機 A）

```bash
cd backend
uv sync
uv run uvicorn app.main:app --reload --port 8000 --ws-ping-interval 10 --ws-ping-timeout 10
```

- 服務位址：http://localhost:8000
- 必須使用**單一 worker**（不要加 `--workers`）；資料只存在記憶體，後端重啟後所有房間都會消失。
- `--ws-ping-interval` / `--ws-ping-timeout` 用來偵測異常斷線，約 20 秒內會把該組判定為離線。

### 2. 前端（終端機 B）

```bash
cd frontend
nvm install   # 第一次使用時安裝 .nvmrc 指定的 Node 22
nvm use
npm install
npm run dev
```

- 開啟 http://localhost:5173
- 開發時 `/api` 與 `/ws` 會由 Vite 代理到後端 8000 埠，不需另外設定 CORS。
- 若瀏覽器打不開 `localhost`，可改用 `npm run dev -- --host 127.0.0.1`，並開啟 http://127.0.0.1:5173。

### 3. 使用方式

1. 老師開啟首頁 → 「我是老師 — 建立房間」，取得房間代碼與恢復碼。
2. 學生開啟首頁 → 「我是學生 — 加入房間」，輸入房間代碼與組名（例如「第 1 組」）。
3. 老師端畫面會即時列出已加入的組別與在線/離線狀態。
4. 學生加入後預設為「等待搶答」且輸入框鎖定；老師按「開始搶答」，全班輸入框即時解鎖；按「結束搶答」再度鎖定（可重複多輪，每輪開始時輸入框清空）。
5. 同一組可以同時開多個視窗（每組最多 10 個），任一視窗送出某題後，其他視窗會同步顯示「已送出」；其他組別只會看到「本題已有組別送出」，看不到答案內容。老師端可看到各組本輪送出的內容與時間。
6. 需要多題一起搶答時，老師在讀取試算表後的預覽畫面勾選**相鄰**的題目（例如 Q3、Q4）按「設為題組」，再確認建立房間（建立後不可修改）。學生端該題組框在同一張卡片內，必須每格都填寫才能用同一顆按鈕整組送出；整組共用同一個名次，結果頁也整組顯示。
7. 活動中或結束後，老師端按「匯出紀錄」可下載所有輪次的作答明細 CSV（欄位：輪次、題號、題組、組別、答案、接收時間、排名；時間為 UTC）。Excel 可直接開啟，中文不會亂碼；答案若以 `=`、`+`、`-`、`@` 開頭，會在前面補一個 `'` 以免被當成公式。紀錄只存在記憶體：房間結束後保留 24 小時、服務重啟就消失，請在活動後盡快匯出；按「回首頁」會清除老師憑證，之後就無法匯出。
8. 搶答結束後，老師在結果面板可對任一筆答案按「駁回/無效」（需填理由，常用理由可快速選取），名次由次順位組別遞補，全班結果即時更新並顯示「老師已更新結果」；誤按可「恢復有效」。原始答案、送出時間與名次不會被改動；老師端有「審核紀錄」，匯出的 CSV 也會附上審核狀態、遞補後名次、審核理由與審核時間。學生在等待搶答階段會看到這個規則說明。目前只提供「判定答案無效」，防壟斷（單組獲勝題數上限）、重開題目、指定獲勝組別尚未提供。
9. 搶答結束後，老師按「回填至 Google Sheet」→ 先看確認摘要（將寫入／略過／清空幾格、其中幾格原有內容會被覆寫）→ 按「確認回填」才寫入。只寫入各題有效第一名的**答案文字**（不含組名、名次）、只回填**最新一輪**；一次批次寫入，全有或全無；答案以純文字原樣寫入（`=1+1` 不會被算成 2、`007` 不會變成 7）；只改作答格，其他儲存格與格式不動；寫入前會再驗證試算表結構，被改動過就拒絕並請重新建立房間。老師審核後可再回填更新；先前由系統寫入、現已無有效答案的格會被清空（老師自己改過的格會保留）。每次回填都有紀錄。不提供「復原」，誤寫請用 Google 試算表的「版本記錄」還原。

## Google 試算表設定（用學習單產生題目）

老師建立房間時可貼上 Google Sheet 連結，系統以專案的 Google 機器人（服務帳號）讀取，產生學生端的填空格。

1. 確認 Google Cloud 專案已**啟用 Google Sheets API**（用服務帳號 JSON 金鑰即可，不需要 API key）。
2. 把服務帳號 JSON 金鑰檔放在專案外或不入版控的位置，**不要提交到 git**。
3. 複製 `backend/.env.example` 為 `backend/.env`，填入金鑰檔的絕對路徑：
   ```
   GOOGLE_SERVICE_ACCOUNT_FILE=/絕對路徑/服務帳號金鑰.json
   ```
4. 打開金鑰檔，複製 `client_email`，把要使用的 Google Sheet「共用」給該 email（只搶答、不回填時，檢視者即可；**要使用「回填至 Google Sheet」，必須設為編輯者**）。
5. 重新啟動後端。未設定時，仍可「直接建立房間（不使用試算表）」。

學習單格式（單題與題組皆自動辨識）：表頭需有「題號」「題目」「作答」；題號欄為數字 1、2、3…（顯示為 Q1、Q2…）；
題組在同一題號下以作答欄的「（1）」「（2）」標示小題，每個小題視為獨立的一題。題號須從 1 起連續且不重複，否則會拒絕建立並列出有問題的題號。

## 其他指令

```bash
# 後端自動化測試（階段同步、廣播不洩漏、鎖定閘門）
cd backend && uv run pytest

# 前端正式建置
cd frontend && npm run build

# 重新產生設計圖 PNG（需安裝 plantuml：brew install plantuml）
plantuml -tpng diagrams/*.puml
# 沒有安裝 Graphviz 時（例如 Windows），可改用 plantuml.jar 內建排版：
# java -jar plantuml.jar -charset UTF-8 -Playout=smetana -tpng diagrams/*.puml
```

## 環境變數（後端，皆選用）

| 變數 | 預設 | 說明 |
|------|------|------|
| `ROOM_IDLE_SECONDS` | `7200` | 房間閒置多久後自動結束（秒） |
| `ROOM_SCAN_SECONDS` | `30` | 閒置掃描間隔（秒） |

例如快速驗證閒置逾時：`ROOM_IDLE_SECONDS=30 ROOM_SCAN_SECONDS=5 uv run uvicorn app.main:app --port 8000`
